# RPGLE 内外网模型对比评测计划

- 计划版本：1.2 Draft，2026-09-06，供评审。
- 适用样本：RPGFLOW-1.0，完全虚构的多仓订单履约与结算系统。
- 当前状态：评测材料与提示词已准备；模型评测尚未执行。
- 本文用于组织执行，不作为被测模型输入；材料及评分口径沿用现有冻结版本。

## 1. 评测目标与边界

在相同可见输入、提示词和只读工具条件下，比较内外网模型对大型固定格式 RPGLE 的静态理解能力，重点观察 Operation Flow、System Flow、Data Flow 和 Transaction Flow。

本轮以公司内部 GPT 配置为基线，优先评估现有 Qwen 模型作为外网自部署方案的表现，DeepSeek 列为后续扩展候选。选择依据是用户希望比较不同模型家族的实际表现；不预设同一提供方的模型能力相近，也不依据开源或闭源属性推定成绩。

评测回答三个问题：

1. 模型能否从万行主程序及配套文件中还原四类流程，而不只是复述代码或背景？
2. 对跨程序、跨文件、正常与异常路径的理解有哪些正确发现、遗漏和错误？
3. 结论是否有可核验证据，多次独立运行的表现是否稳定？

仅使用合成源码与背景，不涉及真实业务资料。不编译、运行或修改 IBM i 程序，不加载测试数据；静态检查及模型分析不代表实际运行验证。首轮不评测代码生成、迁移实现或业务执行正确率。

Copilot 与 Codex 的隐藏系统提示、上下文管理等可能不同。结果应表述为“指定平台与配置下的静态分析表现”，不能声称已经完全隔离平台影响，或由单个合成样本推导所有 RPGLE 系统上的能力。

## 3. 输入与控制条件

### 3.1 统一输入

使用同一份 [RPGFLOW-1.0-files.zip](dist/RPGFLOW-1.0-files.zip)，按 [SHA256SUMS.txt](dist/SHA256SUMS.txt) 核对压缩包。解压后只向模型开放 `input/`。

材料包含 35 个源码文件：7 个固定格式 RPGLE、1 个 CLLE、24 个 DDS、3 个 COPY，以及输入索引和两份必要背景。主程序为 10,114 个物理行。评测版已清理源码注释提示，保留原物理行号和固定格式代码列位置。

两端发送同一份 [prompt.md](prompt.md) 全文，与包内 `input/prompts/run.md` 完全一致。模型应完成四张流程图、解释、证据表和未知事项；不额外发送本计划、完整需求、技术设计、生成技能或评分清单。

### 3.2 工具与会话约束

| 控制项 | 统一要求 |
| --- | --- |
| 会话 | 每次新建空白会话，使用独立的输入目录 |
| 文件范围 | 仅冻结的 `input/` 文件；不读取父目录或其他项目 |
| 允许能力 | 列文件、纯文本搜索、按物理行读取 |
| 调用上限 | 总计 200 次只读工具调用 |
| 单次返回 | 读取最多 500 行；搜索最多 200 个匹配 |
| 累计返回 | 原始工具文本最多 1,048,576 个 UTF-8 字节 |
| 额外能力 | 关闭网络、外部知识库、记忆、额外技能、其他模型及代码执行 |
| 人工干预 | 不解释业务、不提示遗漏、不针对薄弱点追加代码或问题 |

模型自行选择搜索和阅读顺序；只统一能力和预算，不强制两边采取同一路径。工具应返回原文及可核验位置，不在某一端额外启用摘要、语义重排或 RAG 片段筛选。

上下文和输出限制在试跑开始前选定共同可用范围，包含材料、提示词、工具定义、历史和输出余量；用实际 token 口径记录，不能把字符或字节等同于 token。执行端负责计量并保留工具记录；仅将限制写入提示词不等于限制已被落实。

## 4. 执行安排

### 阶段一：首轮试跑，两端各 1 次

建议编号为 `PILOT-IN-01` 和 `PILOT-QWEN-01`。先做内网 GPT，再做外网 `qwen3.5:35b-a3b`；不因先得到的答案改变后一端的提示。

每次按以下顺序操作：

1. 保存输入版本、校验值、配置及运行编号，创建隔离目录和新会话。
2. 发送统一提示词，开始计时，保存工具调用与原始回复。
3. 让模型独立完成四类 Flow，不回答业务澄清问题；缺失信息由模型说明。
4. 仅当输出截断或明显未完成时，使用固定 [continuation.md](input/prompts/continuation.md)，最多两次，记录触发原因。不得借续写纠错。
5. 保存最终报告和所有中间记录，填写执行偏离；按同一评分标准试评。

试跑用于确认材料访问、输出容量、记录方式及评分可操作性，不设模型最低分作为进入正式评测的条件。低分本身是结果，不是应当调整提示的理由。

试跑完成后作一次方法复核：

- 材料、权限、日志和预算可核验，评分点可用：按相同版本进入正式评测。
- 存在输入截断、工具配置问题或必要的协议修改：统一处理，两端重新试跑；涉及冻结输入、提示词或评分基准变更时建立新版本。
- 某些执行条件无法观察或落实：保留探索性结果，注明限制，不能标为严格受控。

试跑结果单独报告，不并入正式 3 次结果；不依据哪一方得分较低进行定向调优。

### 阶段二：正式评测，每组 3 次

本计划拟定每组 3 次独立运行，共 6 次；在首次正式运行前固定次数。每次使用新会话，模型不接触先前报告或评分。

| 次序 | 运行编号 | 配置组 |
| --- | --- | --- |
| 1 | FORMAL-IN-01 | 内网 |
| 2 | FORMAL-QWEN-01 | 外网 `qwen3.5:35b-a3b` |
| 3 | FORMAL-QWEN-02 | 外网 `qwen3.5:35b-a3b` |
| 4 | FORMAL-IN-02 | 内网 |
| 5 | FORMAL-IN-03 | 内网 |
| 6 | FORMAL-QWEN-03 | 外网 `qwen3.5:35b-a3b` |

使用交错次序，保持同一组的模型、设置、提示和执行规则不变。不选择性保留最好答案，也不因低分追加运行。模型漏读、误解或未完成是观察结果；连接中断、工具服务故障等基础设施问题单独标注。确需补跑时保留失败记录，使用新的运行编号并说明原因，不覆盖原记录。

### 阶段三：匿名评分与差异分析

由操作员为报告分配不暴露模型名称的匿名编号，配置映射单独保存。评审者使用匿名报告、冻结输入及评分参考核对，不向被测模型反馈评分内容。

先逐点评分，再对有争议的事实、证据位置和疑似代码问题复核。条件允许时由第二位评审者独立复核争议项。参考清单为 Draft；源码与设计不一致时以冻结源码为准。评分基准如需修订，保存版本和裁决，并对同一比较组全部重评。

## 5. 评分与观察指标

沿用 [rubric.md](reference/rubric.md) 和 [evidence-checklist.md](reference/evidence-checklist.md)，不另设竞争性评分口径。

| Flow | 分值 | 主要观察内容 |
| --- | ---: | --- |
| Operation Flow | 25 | 角色、触发与时点、人工介入、异常处置和结果交接；区分背景与代码行为 |
| System Flow | 25 | 外部边界、输入输出、信息方向和内部职责；不以程序调用图代替系统边界 |
| Data Flow | 25 | 关键身份、数量、金额与状态的来源、计算、关联和写入，及异常影响 |
| Transaction Flow | 25 | 业务事件的跨程序路径、成功／拒绝／等待／恢复分支，以及数据库事务边界 |
| 合计 | 100 | 每条 Flow 5 项，每项 5 个计分点，每点 1 分 |

计分点需同时满足事实正确、证据具体有效、代码／背景／推断分类恰当。缺失、错误或无可核验证据均不得分，不给半分。Operation 和 System 中的外部设定可引用背景；代码行为须有源码证据。

另外报告以下指标，不混入总分：

- 有效证据比例：可支撑对应结论的证据条数／已核查证据条数，同时给出分子、分母及核查范围；没有证据时记为 null。
- 明确误报及重要遗漏：分别列出实例与源码位置；没有对应计分点的误报不临时新增负分。
- 交付完整性：四类 Flow 的图、解释、证据表及未知事项是否齐全，不重复扣除事实分。
- 执行表现：耗时、工具调用、可取得的 token 用量、续写次数和条件偏离；耗时不计入理解能力分。
- 稳定性：展示每次得分、各 Flow 与总分的中位数及最小／最大值，不以 3 次运行宣称统计显著。

不按答案篇幅或图的美观程度加分，不临时设置“及格线”。合理的新发现与疑似源码缺陷先核实，再按相同规则裁决。

## 6. 记录与交付

建议每次运行保存到 `runs/<运行编号>/`。保留原始模板，不直接填改冻结模板文件。

| 交付 | 内容及入口 |
| --- | --- |
| 运行记录 | 复制 [run-template.json](runs/run-template.json)，填写实际配置、输入版本、时点、用量和偏离 |
| 原始证据 | 实际发送的提示、全部工具日志、原始回复及续写记录 |
| 分析报告 | 四类 Flow 最终报告；保留原文，不替模型修正事实 |
| 评分记录 | 复制 [score-template.csv](runs/score-template.csv)，逐点记录答案、证据及裁决 |
| 比较汇总 | 使用 [comparison-template.csv](runs/comparison-template.csv)，试跑与正式运行分开 |
| 结论报告 | 各次及汇总得分、稳定性、典型差异、错误案例与适用限制 |

本阶段计划共 8 次分析运行：2 次试跑、6 次正式运行；异常补跑另行列出。模型得分与耗时在执行前保持空白，不预填估计值。

## 7. 完成条件与结论范围

完成条件是约定运行已执行或明确记录未完成原因，原始记录可追溯，四条 Flow 评分可核验，争议项有裁决，比较报告保留条件差异和失败案例。尚未满足共同条件的运行单独列出，不与受控结果合并。

最终应说明：在本样本和配置下，哪一组在哪些 Flow 上覆盖更完整、证据更可靠、错误更少、波动更小，以及这些差异是否受输入或工具限制影响。单一样本结果不用于证明真实系统迁移成功，也不直接作全面模型排名。

目前只准备和评审计划，不启动模型、不修改冻结材料、不提交或推送。后续执行时以本计划、[运行说明](runs/README.md)及冻结版本记录共同约束操作；发现冲突应先统一口径，不在单次运行中临时改变规则。
