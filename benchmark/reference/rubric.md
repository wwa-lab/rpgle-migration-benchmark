# 四类 Flow 评分办法

状态：Draft。适用材料：RPGFLOW-1.0。仅供评审人员使用。

每条 Flow 包含 5 项，每项 5 个计分点；每点 1 分，总计 100 分。计分点写在 evidence-checklist 中，没有隐藏的额外加分规则。

## 单个计分点如何判断

只有同时满足以下条件才得 1 分：

1. 答案表达该事实或等价关系，没有与其直接相反的结论。
2. 引用正确的输入源码位置或题目背景小节，证据能支撑这个具体事实。只有文件名或覆盖整个万行文件的笼统引用不够。
3. 将代码事实、题目背景和推断分开；不把静态路径或外部说明描述成已运行验证的保证。

缺失、错误、无可核验证据均为 0 分，不给半分。同一事实不要求使用固定措辞；额外正确发现可以记录，但不突破每项 5 分。全新、合理的代码缺陷应先核实，再统一裁决相关计分点，不能因偏离设计意图扣分。

## 图与文字

四类 Flow 都应有图、解释、证据表和未知事项。计分点可以由图或文字表达，但图中与正文相矛盾的关键条件会使对应点不得分。没有某条 Flow 图，记为交付格式不完整并单独报告，不额外重复扣除已失去的事实分。

Operation Flow 的角色／时点可以引用背景得分；System Flow 的外部边界可以引用背景，但核心出入口、文件写入和内部调用应引用源码。Data Flow 与 Transaction Flow 的行为点必须有代码证据。

## 误报与未覆盖发现

额外记录模型明确声称但证据不支持的内容，例如臆造网络协议、真实发送成功、运行测试通过，或把消息送达等同财务成功。误报关联已有计分点时该点为 0；没有关联时列入误报清单，不临时创造负分惩罚。

有效证据比例 = 实际可支撑相应结论的证据条数 / 已检查的证据条数。没有证据时记为 null 并注明“未提供”，不要填 100%。该指标、格式完成度、误报数、耗时和总分分别报告。

## 双人复核与盲评

条件允许时，两位评分者独立标注有争议项，再记录统一裁决。评分前隐藏模型标签，评分后再关联运行配置。参考版本变化会影响评分时，同一比较组全部重评，不只调整某一模型。
